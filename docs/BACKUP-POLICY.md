# وثيقة سياسة النسخ الاحتياطي وحماية البيانات | رَواق RAWAQ

## 1. نظرة عامة
تحدد هذه الوثيقة السياسة الرسمية والدائمة لحماية بيانات متجر ولوحة إدارة **رَواق | RAWAQ** (أناقة من روح الأصالة). تضمن هذه السياسة حماية تامة وغير منقطعة لكافة البيانات التجارية، المنتجات، الموردين، الطلبات، الفواتير، الملفات، والصور مع الاحتفاظ بأحدث نسختين ناجحتين ومحققتين بالكامل.

---

## 2. البنية التحتية ومسؤوليات الخدمات

| الخدمة | الدور والمسؤولية | طبيعة البيانات |
| :--- | :--- | :--- |
| **Supabase Database** | قاعدة البيانات الإنتاجية الرئيسية | العمليات اليومية، الطلبات، المنتجات، الحسابات، والمستخدمين. |
| **Supabase Storage** | التخزين السحابي للوسائط | صور المنتجات، صور الأقسام، الشعار، الفواتير، والمستندات. |
| **Neon PostgreSQL** | قاعدة النسخ الاحتياطية المخصصة | استعادة وفحص النسخ الاحتياطية في مخططات معزولة (`backup_xxx`). لا يوجد أي ربط تشغيلي مباشر مع المتجر. |
| **Cloudflare R2 / S3** | تخزين الأرشيف المشفر المستقل | حفظ أرشيفات ZIP المشفرة بتشفير AES-256 خارج بيئة Supabase. |
| **GitHub Actions** | الجدولة والأتمتة | تشغيل دورة النسخ التلقائية كل 48 ساعة وإجراء اختبارات الاستعادة الشهرية. |
| **Resend** | منصة الإشعارات والبريد | إرسال إشعارات الطلبات الجديدة وتقارير نجاح وفشل النسخ الاحتياطي بالهوية الرسمية لرَواق. |

## 3. القاعدة الذهبية: سياسة الاحتفاظ بنسختين فقط (2-Backup Retention Policy)
1. **دورة النسخ**: تتم عملية النسخ الاحتياطي الشاملة كل 48 ساعة (الساعة 03:17 فجراً بتوقيت الأردن / 00:17 UTC).
2. **الحد الأقصى للنسخ المعتمدة**: يتم الاحتفاظ بآخر **نسختين ناجحتين فقط** في Neon وأرشيف التخزين السحابي.
3. **شرط الحذف الإلزامي**:
   - **يُمنع منعاً باتاً** حذف أي نسخة قديمة قبل اكتمال النسخة الثالثة الجديدة بنسبة 100% والتحقق من تطابق كافة سجلاتها وجداولها.
   - أثناء عملية النسخ، تتواجد 3 نسخ مؤقتاً في النظام.
   - فور اعتماد النسخة الثالثة بنجاح، يقوم النظام تلقائياً بحذف النسخة الأقدم (النسخة الأولى).
   - إذا حدث أي فشل في النسخة الجديدة، تتوقف العملية فوراً، وتظل النسختان السابقتان سليمتين ومحميتين دون أي تغيير.

## 4. نطاق البيانات المشمولة بالنسخ
يشمل الأرشيف الكامل لبيانات رَواق ما يلي:
- **المنتجات والأقسام**: المنتجات، الخصائص، القوالب، الأسعار، المجموعات، والعلامات التجارية.
- **الطلبات والعملاء**: الطلبات، تفاصيل الأصناف، الحالات، العملاء، والعناوين.
- **الشركاء والموردون**: حسابات الموردين، المواقع، عروض الأسعار، والمستحقات.
- **المالية والمحاسبة**: المعاملات المالية، الفواتير، الأرباح، الرواتب، وتوزيعات الشركاء.
- **التوصيل والطرود**: بوالص الشحن، الدفع عند الاستلام (COD)، والمناطق.
- **الأمان والصلاحيات**: الموظفون، الأدوار، الصلاحيات، وسجلات الدخول.
- **سجلات التدقيق**: سجلات مركز الرقابة والتدقيق `/admin/logs` كاملة.
- **وسائط التخزين (Storage)**: كافة الملفات الفعلية في حاويات `brand-assets`، `product-images`، `uploads`، `invoices`، وغيرها.

## 5. معايير الأمان والتشفير
1. **تشفير الأرشيف**: يُشفر كل ملف أرشيف ZIP بتشفير **AES-256-CBC** مع مفتاح استرجاع خارجي مستقل (`BACKUP_ENCRYPTION_KEY`).
2. **عزل Neon**: يتم استعادة كل نسخة في مخطط PostgreSQL مستقل تماماً يبدأ بالبادئة `backup_`، مما يحول دون التداخل مع أي بيانات أخرى.
3. **عدم تخزين الأسرار**: لا يحتوي ملف `manifest.json` أو ملفات الإعداد داخل الأرشيف على أي مفاتيح سرية أو كلمات مرور.

- **نجاح النسخ**: تقرير فني شامل يوضح رقم النسخة، الحجم، المدة، والنسخة التي حُذفت والنسختين المتبقيتين.
- **فشل النسخ**: تنبيه أمني عاجل مع تحديد مرحلة وسبب الفشل والتأكيد على بقاء النسخ السابقة سليمة.
- **منع التكرار**: استخدام `Idempotency-Key` لمنع تكرار إرسال الرسائل في حالات إعادة المحاولة.
- **عنوان الرد (Reply-To)**: موجه ومثبت تلقائياً على بريد الإدارة الرسمي `rawaq.rq@gmail.com`.
